MODEL / REASONING / USAGE
- Recommended configuration: `Terra Medium`.

CONTEXT

Read BOOT.md first, then README.md, AGENTS.md, docs/README.md, docs/architecture.md, docs/template-system.md, docs/roadmap/initial-roadmap.md, docs/codex-model-selection.md, the Phase 2 task stack under docs/tasks/p2/, and the current template/story-workspace implementation and tests before editing.

Phases 1 and 2 are already closed and the repository is on the 0.3.0 Phase 3 baseline. This correction must not roll the roadmap back, advance it, or change package/src versioning.

Human review found one bounded Phase 2 defect after closeout:

- `default-news-40s` is correctly represented as declarative template data;
- however, `validateAssemblyTemplate()` still enforces exactly four segments ending at exactly 40 seconds;
- therefore a valid 25-second, 60-second, or otherwise differently structured template cannot be added as data without changing the generic core validator.

That violates the accepted template-system standard: templates own clip structure, and adding another template should normally require a new declarative definition rather than changes to story reasoning or generic temporal validation.

The current 1080x1920 / 30 fps / H.264 MP4 output baseline is intentionally still a project-wide MVP constraint. Do not broaden output-format support in this correction. The defect is generic template timing/segment-shape extensibility, not deferred 16:9/1:1 support.

This single correction prompt intentionally combines the bounded fix with the correction closeout validation.

GOAL

Repair the AssemblyTemplate validation boundary so generic validation accepts any supported declarative template with a non-empty, contiguous, ordered, positive-duration segment sequence beginning at 0, while keeping all exact `default-news-40s` timing and role semantics owned by `templates/default-news-40s.json` and its focused tests.

Then rerun the complete relevant Phase 2 evidence and leave the unchanged 0.3.0 repository review-ready.

TARGET BEHAVIOR

Generic template contract:

    template data
        |
        v
    generic structural validation
        |
        +-- non-empty segment list
        +-- unique segment IDs
        +-- first segment starts at 0
        +-- positive durations
        +-- contiguous ordered timing
        +-- references resolve to declared slots/roles
        +-- current supported output contract
        +-- standardized intro/outro contract
        |
        v
    valid AssemblyTemplate

Default-specific contract:

    templates/default-news-40s.json
        |
        v
    exactly:
      0-5   hook
      5-15  content
      15-28 support
      28-40 closing

The generic validator must not know that a normal template has four segments or a 40-second terminal duration.

IMPLEMENTATION REQUIREMENTS

1. Remove default-template shape from generic validation.
   - Inspect `src/core/assembly-template.ts`.
   - Remove the generic rule that requires exactly four logical segments totaling 40 seconds.
   - Do not replace it with a different hard-coded segment count or terminal duration.
   - Preserve the existing generic segment validation that starts from time 0 and rejects gaps, overlaps, reversed/out-of-order timing, non-finite values, zero/negative durations, duplicate IDs, duplicate references, and undeclared references.
   - Keep malformed templates fail-closed with the existing `assembly_template` error boundary.

2. Preserve current MVP output support.
   - Keep the current 1080x1920, 30 fps, H.264/MP4 output constraint unless an existing test/schema mismatch requires a strictly bounded alignment repair.
   - Do not add 16:9, 1:1, arbitrary codecs, arbitrary frame rates, responsive output, or media normalization behavior.
   - This correction is not Phase 5 rendering work.

3. Keep `default-news-40s` exact.
   - Do not weaken or alter the locked default template.
   - Focused default-template tests must continue proving:
     * template ID/version;
     * 0-5 hook;
     * 5-15 content;
     * 15-28 support;
     * 28-40 closing;
     * exact 40-second logical duration;
     * 1080x1920 at 30 fps;
     * hook/headline opening-anchor requirements;
     * generated content-video + content-voiceover;
     * support + closing reuse of `supporting-anchor`;
     * standardized intro/outro roles.

4. Add direct extensibility proof.
   - Add a focused test that constructs or loads at least one second valid template shape whose segment count and total duration differ from `default-news-40s`.
   - Prefer a small in-test synthetic definition rather than adding a second product template that the owner has not requested.
   - Example acceptable proof: a valid contiguous 25-second template with a different number of segments.
   - The alternate definition should use the current supported output baseline and valid declared content/generated/standardized roles.
   - Prove it passes `validateAssemblyTemplate()` without modifying the validator for that template ID, segment count, segment IDs, or total duration.
   - This test is the focused regression guard for the defect.

5. Schema/runtime alignment.
   - Inspect `schemas/assembly-template.schema.json`.
   - Do not change the schema merely for churn: it already appears not to encode the four-segment/40-second restriction.
   - If a change is actually necessary to keep runtime/schema semantics coherent, keep it minimal and explain why.
   - Preserve strict additionalProperties behavior and existing role/type constraints.

6. Template registry scope.
   - Do not build filesystem discovery, plugins, inheritance, hot reload, or a template marketplace.
   - The current small built-in registry may remain.
   - This correction only needs to prove that the generic template contract itself does not force the default-news-40s temporal shape.

7. Preserve Phase 2 story behavior.

   - Do not change the manual ngest-shaped ingress contract.
   - Do not change story workspace identity/layout/status semantics unless a regression caused by the template fix is discovered.

   - `src/version.ts` must remain 0.3.0.
