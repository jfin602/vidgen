TASK: Phase 3 / P1 — Template slot authoring semantics

MODEL / REASONING / USAGE
- Recommended configuration: `Terra Medium`.

VERSIONING
- This prompt's assigned project version is `0.3.1`.

CONTEXT

Read BOOT.md first, then README.md, AGENTS.md, docs/README.md, docs/architecture.md, docs/template-system.md, docs/roadmap/initial-roadmap.md, the completed Phase 2 task stack, correction c2-fix, and the current AssemblyTemplate implementation/schema/tests before editing.

Phase 3 is now a direct StoryInput + AssemblyTemplate -> ClipPlan phase. Core ClipPlan generation must remain template-generic. The model cannot fill arbitrary template slots safely if the template only exposes opaque slot IDs such as "hook" or "narration"; the template itself must carry the small amount of authoring guidance needed to explain each slot.

PRECONDITION

Correction c2-fix must already be applied before this task executes.

Verify that the generic AssemblyTemplate validator no longer hard-codes exactly four segments or a 40-second terminal duration. If the correction is absent, do not absorb that correction into this Phase 3 task and do not re-plan around the stale implementation. Stop and report the repository precondition clearly.

GOAL

Extend the declarative AssemblyTemplate content-slot contract so every slot describes how it should be filled without teaching core ClipPlan logic the meanings of default-news-40s slot IDs.

Conceptual slot:

    {
      id,
      usage,
      instruction
    }

Current initial usages:

    spoken
    display

SCOPE

Implement:
- required content-slot authoring semantics in the AssemblyTemplate TypeScript/runtime contract;
- matching AssemblyTemplate JSON Schema changes;
- updated default-news-40s declarative slot data;
- appropriate template/schema versioning;
- focused regression/extensibility tests.

IMPLEMENTATION REQUIREMENTS

1. Content-slot semantics.
   - Extend AssemblyTemplateContentSlot to require:
     * id: existing stable slot identifier;
     * usage: exactly "spoken" or "display" for the current MVP;
     * instruction: non-empty human/model-facing authoring guidance.
   - Keep the contract deliberately small.
   - Do not add provider parameters, model IDs, temperature, prompt fragments, asset paths, media prompts, or generated content.

2. Generic validation.
   - Runtime validation must:
     * reject unsupported usage values;
     * reject blank instructions;
     * reject unsupported extra fields;
     * preserve unique content-slot IDs;
     * keep all corrected generic segment timing/reference checks from c2-fix.
   - Do not reintroduce a four-segment/40-second assumption.
   - Do not hard-code default slot IDs in the generic validator.

3. Schema/versioning.
   - This is a real template-contract format change.
   - Bump AssemblyTemplate schemaVersion coherently rather than silently changing the meaning of schema version 1.
   - Update the JSON Schema const and runtime constant together.
   - Bump the built-in default-news-40s template's own version because its declarative authoring contract changes and future ClipPlans record template ID/version.
   - Update existing story-workspace/template tests and expected metadata coherently.
   - Do not retain a fake compatibility parser for the old format unless an actual current consumer requires it; this is early-stage and there is only one built-in production template.

4. default-news-40s guidance.
   - Preserve exact segment timing and generated/standardized asset roles.
   - Give every existing slot concise generic authoring semantics equivalent to:
     * hook: spoken; short presenter opening hook grounded in the supplied story;
     * headline: display; concise on-screen headline treatment;
     * narration: spoken; voiceover explaining the core story during the content beat;
     * supporting-information: spoken; strongest useful supporting detail for the presenter;
     * closing: spoken; brief concluding statement that adds no unsupported new facts.
   - The exact wording is implementation-owned, but keep it concise and factual.
   - Do not encode provider prompts or model-specific syntax.

5. Extensibility regression.
   - Preserve the c2-fix proof that an alternate synthetic template with a different segment count and non-40-second duration passes generic validation.
   - Update that synthetic test definition to include valid slot authoring semantics.
   - Add focused proof that arbitrary non-default slot IDs with valid usage/instruction do not require source-code changes.

6. Current output boundary.
   - Preserve the current 1080x1920 / 30 fps / H.264 MP4 output support.
   - Do not expand aspect ratios, codecs, or frame rates in this task.

7. Version/test wiring.
   - Set package.json and src/version.ts to 0.3.1.
   - Keep package-lock.json absent.
   - Keep all existing tests wired into npm test/check.
