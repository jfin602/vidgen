TASK: Correction 6 / P2 — File-driven Veo prompts with no hardcoded prompt prose

MODEL / REASONING / USAGE
- Recommended configuration: `Terra High`.

VERSIONING
- Required unchanged project version: `0.6.5`.

GOAL

Remove Veo prompt prose from TypeScript. All Veo prompt wording, including presenter wording, the AI-generated-reference disclaimer, exact-dialogue instructions, story-grounding prose, continuation instructions, no-extra-dialogue rules, on-screen-text rules, unsupported-fact rules, and B-roll/content wording must come from one bounded operator-owned local prompt-spec file. Source code may select a template and substitute validated dynamic values, but must not contain fallback or appended Veo prompt sentences.

Read BOOT.md, Google video integration notes, current Agent Platform Veo adapter, provider-neutral video/presenter contracts, video client factory, headline workflow/sidecar, cinematic media workflow/reuse fingerprinting, generated-media schemas, and focused tests before editing.

PROMPT FILE CONTRACT

Add one runtime setting:

`VIDGEN_VEO_PROMPT_FILE`

Production may point it at:

`/home/deploy/vidgen-assets/prompts/veo-prompts.json`

Do not hardcode that deployment path in source.

Use one strict, bounded UTF-8 JSON prompt-spec file. The exact field names may be chosen narrowly, but it must provide distinct templates for every current Veo prompt shape:
- simple presenter initial request without extension;
- simple presenter initial request when an extension will follow;
- simple presenter extension;
- cinematic presenter initial;
- cinematic presenter extension;
- cinematic content/B-roll initial;
- cinematic content/B-roll extension.

The file is the sole owner of provider-sent Veo prose. It must be able to contain the owner's disclaimer itself, for example:

`The supplied reference images are AI-generated presenter images and do not depict a real person or celebrity.`

That sentence must NOT exist as a hardcoded source string.

The owner's starting file will use `presenter` rather than `news-presenter`. Do not hardcode or rewrite either word in source; prompt wording belongs to the file.

TEMPLATE SUBSTITUTION

Support only a small fixed placeholder vocabulary required by current behavior, such as:
- `{{dialogue}}`;
- `{{context}}`;
- `{{retainedExtensionSeconds}}`.

Use separate prompt-spec fields where conditional prose would otherwise have to be hardcoded, including the simple initial-with-extension case.

Validate that each template contains exactly the placeholders its request shape requires and no unknown placeholders. Replacement must be one-pass/non-recursive: dynamic dialogue or story text that happens to contain placeholder-looking text must remain literal data and must not become template syntax.

The engine may own only structural mechanics:
- selecting the correct prompt template;
- substituting validated dynamic values;
- choosing request/reference/video payload fields;
- duration/extension planning;
- provider/auth/polling/result handling.

No provider-sent Veo instruction sentence may be appended, prepended, or used as a fallback in TypeScript. Missing or invalid prompt configuration must fail rather than silently use the old hardcoded prompts.

INPUT / FAILURE SAFETY

- Require a regular local file, valid UTF-8/JSON, strict expected shape, nonblank bounded template strings, and a small explicit maximum byte size.
- Reject missing, unreadable, non-file, malformed, oversized, unknown-field, missing-template, or invalid-placeholder specs with sanitized configuration/generation errors.
- Do not expose prompt contents, absolute paths, raw filesystem errors, credentials, or provider headers in public errors/artifacts.
- Validate the prompt asset before any paid provider call in the simple headline flow. In cinematic media generation, validate before the first provider generation call when video units are required.
- Read one stable byte snapshot per configured client/run so request construction, identity, and provenance cannot disagree if the file changes mid-run. A later run may pick up new bytes.

GENERATION IDENTITY / PROVENANCE

Editing the prompt file must affect generation identity without a code change.

Define a safe prompt-asset identity containing only:
- basename;
- SHA-256;
- byte size.

Do not persist prompt text or absolute paths.

- Expose the active prompt-asset identity through the provider-neutral video/presenter client boundary in the narrowest reusable form.
- Include the prompt identity in simple headline sidecar provenance. Bump the headline sidecar schema version because its shape changes.
- Include the prompt identity in cinematic video generated-media provenance. Bump the generated-media/media-run schema version where required by the durable shape.
- Include the prompt identity in effective generation fingerprinting for every Veo video unit, presenter or content, so a prompt-file edit cannot reuse stale Veo media.
- Voiceover/TTS reuse must remain unaffected by Veo prompt-file changes.
- Existing video records lacking the new prompt identity must not be treated as reusable under the new contract.

PRESERVED BEHAVIOR

Preserve:

The prompt file changes wording/configuration only. It does not bypass provider safety classification and no live safety outcome may be claimed from mocked tests.
