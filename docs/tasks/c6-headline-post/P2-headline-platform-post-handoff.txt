TASK: Correction 6 / P2 — Headline platform post handoff

MODEL / REASONING / USAGE
- Recommended configuration: `Terra High`.

VERSIONING
- Required unchanged project version: `0.6.5`.

GOAL

Add a fresh VidGen CLI command that hands a completed simple headline clip to the independently installed VidGen Poster for the explicitly selected publishing network while keeping all platform implementation owned by jfin602/vidgen-poster.

Start from the P1 dry-run result. Inspect the current VidGen CLI/headline result contract and the current VidGen Poster CLI/platform contract before editing. Do not import Poster source code or reimplement platform behavior.

MUST REMAIN TRUE

- Add `vidgen headline-post` with the same headline generation inputs as `vidgen headline`, including `--dry-run`, plus required `--platform <bluesky|meta|x>`.
- `--platform` must accept exactly `bluesky`, `meta`, or `x`; it has no implicit/default network. Missing, repeated, or unsupported values fail before any generation or Poster process call.
- The selected platform is used unchanged for both Poster readiness and publication: `doctor <platform>` and `post <platform> --video <finished-mp4> --text <caption>`.
- Platform-specific authentication, validation, upload, duplicate protection, receipts, API behavior, and capability support remain entirely owned by VidGen Poster. VidGen contains only the strict platform allowlist and orchestration.
- Current Poster support must be treated as runtime truth. If the configured Poster build does not yet support the selected platform (including `x`), its doctor failure must stop safely before paid generation; VidGen must not fallback to another network or fake platform readiness.
- The Poster installation root is runtime configuration via `VIDGEN_POSTER_ROOT`; do not hardcode a deployment path.
- Invoke Poster only as an external process from the configured Poster repository/runtime using argument-vector execution with no shell interpolation. Platform, headline/source text, and paths are untrusted values and must remain discrete arguments.
- Before paid structured-text/Veo generation, normal `headline-post` must complete the reusable local headline preflight and a successful Poster `doctor <selected-platform>` readiness check.
- After readiness succeeds, run the existing normal headline generation path. Poster `post` may occur only after the finished MP4 and coupled sidecar reach the existing successful headline publication boundary.
- Caption text for every selected platform is exactly `"<headline>" by <source display name>`, using the same governed Article/source identity that produced the clip. Do not summarize, rewrite, add hashtags, or generate social copy.
- A real run must not pass Poster `--dry-run`; publication is delegated to the selected platform normally.
- `headline-post --dry-run --platform <platform>` must run Poster `doctor <platform>` and the P1 headline dry-run contract. It still performs structured-text presenter-copy generation and persists P1 inspection artifacts, but suppresses Veo and must never invoke Poster `post`, upload media, or create an external post.
- If headline generation fails, Poster post must never run. If Poster publishing fails after generation, preserve the completed VidGen MP4/sidecar, return nonzero, and report a safe publication-stage failure.
- Do not forward or persist raw child stdout/stderr as trusted diagnostics. No secrets, authorization data, tokens, raw provider responses, or shell command strings may enter VidGen artifacts or public errors.
- Do not add a VidGen `--allow-duplicate` path; Poster remains the duplicate/publication authority.
- Existing `headline`, its P1 dry-run behavior, and all cinematic commands remain unchanged.
- Package and engine version remain 0.6.5.
